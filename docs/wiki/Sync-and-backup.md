# Синхронизация и резервные копии

**Setting sync** поддерживает облачный/custom backend, WebDAV и gist-механизмы. В этой сборке cloud endpoint задаётся административной политикой. Автоматическая синхронизация может быть включена по умолчанию, но без настроенных реквизитов провайдера успешная передача не гарантируется.

## Безопасная настройка

1. Сохраните отдельную резервную копию исходного профиля.
2. Выберите провайдера и настройте реквизиты в форме, не в публичном сообщении.
3. Проверьте направление: upload отправляет локальные изменения, download получает серверные.
4. Сначала проверьте несекретную закладку и восстановление в изолированной среде.
5. Проверьте сообщения результата; пустая удалённая коллекция и ошибка расшифровки — разные состояния.

Пароль синхронизации не равен паролю приложения. В текущей реализации при заданном sync-пароле шифруются закладки и профили; нельзя обещать, что все настройки и метаданные тоже зашифрованы. Подставленный plaintext вместо ожидаемых зашифрованных данных должен отклоняться.

Secret gist — не общедоступная страница, но и не криптографическая защита сам по себе. Ограничивайте права токена и не делитесь gist ID с секретами. Для WebDAV сохраняйте проверку TLS.

## Backup

Синхронизация не заменяет версионную резервную копию: ошибочное изменение может распространиться. Копия БД не гарантирует восстановление OS-bound ключей на другом аккаунте. Не копируйте пользовательский keychain в SYSTEM и не удаляйте исходный профиль до проверки восстановления.

## Export/import из файла

В **Settings → Sync** есть экспорт/импорт файла для поддерживаемых sync-данных: закладок и групп, тем, быстрых команд, профилей, адресных закладок, workspaces, triggers и конфигурации. Экспорт создаёт plaintext JSON `*-electerm-all-data.json`, который может содержать секреты; храните его как конфиденциальную резервную копию.

Импорт заменяет соответствующие коллекции и конфигурацию, а не объединяет их. Это не полная копия БД: история, логи, uploads и managed identity не включены. Конфигурация синхронизации может сохранить прежние endpoint, пользователя/токен и automatic-sync настройки. Перед экспортом проверьте/отключите autosync; на новом сервере явно настройте нужные реквизиты и не включайте autosync, пока не проверили импорт. Если используется пароль шифрования sync-данных, сохраните его отдельно: он не является `SERVER_SECRET`.

Полный file-level перенос standalone Web — отдельная операция с остановленным сервисом; см. [руководство по миграции](../MIGRATION.md#web-data-backup-and-restore). Raw SQLite backup не является гарантией шифрования на диске.
