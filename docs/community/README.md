# 🤝 План сообщества Anubis

**Это редакционный пакет, а не объявление об открытом форуме.** Таблица ниже предлагает категории для возможной будущей настройки GitHub Discussions; эта страница не создаёт их и не утверждает, что Discussions или GitHub Wiki уже опубликованы. Проверьте живую страницу и настройки отдельно перед добавлением публичных ссылок.

Подготовленные FAQ и сценарии в [STARTERS.md](STARTERS.md) написаны от лица команды и помечены как редакционные заготовки. Не выдавайте их за вопросы пользователей или состоявшиеся разговоры. Частный кандидат `5.7.5` не является выпущенным runtime.

## Категории

| Категория | Формат GitHub | Для чего | Стартовая тема |
| --- | --- | --- | --- |
| Announcements — 📣 Объявления | Announcements | Проверенные релизы, изменения и ограничения; пишет команда | Что подтверждено для текущего релиза |
| Q&A — ❓ Вопросы и ответы | Q&A | Конкретные вопросы с отмеченным ответом | Как выбрать Desktop, Web или managed |
| Ideas — 💡 Идеи | Open-ended discussion | Проблема пользователя, сценарий и критерий пользы | Как улучшить выбор workspace без путаницы |
| Show and tell — 🧭 Практика | Open-ended discussion | Проверенные инструкции и разборы | Безопасное первое SSH-подключение |
| General — 💬 Общение | Open-ended discussion | Знакомство, рабочие привычки, обратная связь | Какие задачи вы решаете клиентом |
| Polls — 📊 Опросы | Polls | Только решения, по которым команда готова действовать | Какой раздел Wiki-ready документации уточнить первым |

Q&A не заменяет bug tracker. Баг с воспроизводимыми шагами переносится в issue со ссылкой на обсуждение без дублирования секретных вложений. Уязвимости направляются в приватный канал.

## Темы и маркировка

Для заголовков/поиска полезны темы `desktop`, `web`, `managed-access`, `windows-workspace`, `ssh-sftp`, `remote-desktop`, `mcp`, `sync`, `documentation`. Это предложение тематизации, не обещание отдельной функции «тегов» Discussions.

Публиковать от команды: подпись **FAQ сопровождающих** либо **Сценарий для обсуждения**. В Q&A ответ отмечается после проверки, не автоматически ради статистики.

## Работа с ответами

Сначала уточнять режим и версию, затем давать безопасный следующий шаг. Для непроверенной функции писать «не подтверждено», для PRO-заглушки — «не реализовано». Не обещать срок исправления без решения команды.

Один полезный материал лучше серии пустых сообщений. Подготовленные примеры находятся в [STARTERS.md](STARTERS.md); публикуйте их только после проверки фактов и отдельного решения сопровождающих. Не создавайте подставные аккаунты и не изображайте пользовательский спрос.
